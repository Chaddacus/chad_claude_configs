# Testing Standard (Global Baseline) v1.0

This standard defines what "testing" means as a verification gate. It is the
authoritative spec referenced by `validator` agent, `auto_runtime`'s
verification profile detection, and the `test_breadth_check` postflight gate.

LLMs cheat on testing by default — they smoke-test, eyeball the result, and
move on. This document defines the *minimum* breadths required for a slice
to be marked complete, with explicit triggers so there's no ambiguity about
which breadth applies.

## Core Principle

**Tests verify behavior, not just absence of crash.** A passing smoke test
is not evidence that a function works. Evidence is: the function was
exercised across the input space relevant to its contract, the output was
checked against expected behavior, and any side effects were observed.

If you cannot point at evidence of input-output verification across the
relevant input space, you have not tested. Run the appropriate breadth.

## The Four Breadths

### 1. `smoke`

Runtime imports + sanity assertions. Just confirms the module loads and a
trivial happy-path assertion holds.

**Acceptable when:**

- Pure refactor on a covered surface (existing tests pass unchanged).
- Doc-only change (markdown, comments, README).
- Dependency bump where typecheck and existing tests pass.
- Configuration value change with no behavioral semantics (e.g. log level).

**Insufficient when:**

- Any behavioral logic was added or changed.
- Adjacent surfaces (per the escalation rule below) are reachable from the
  edit.
- Pure refactor on an **uncovered** surface — characterization tests must
  pin current behavior before the first transform lands (procedure:
  `~/.claude/skills/refactor/SKILL.md`).

### 2. `full`

Project-native test suite for the changed module — `pytest <module>`,
`vitest run <pattern>`, `jest <pattern>`, `cargo test <module>`,
`go test ./<pkg>/...`, etc.

**Required when:**

- Any logic change not covered by `smoke`.
- New unit-testable function or method.
- Bug fix on existing logic.
- Internal API change with consumers in the same module.

**What it must do:**

- Run the suite for the changed surface, not the whole project (full-suite
  is reserved for task closure per `~/.claude/CLAUDE.md`).
- Existing tests must still pass.
- New tests required for new logic, including at least one boundary case.

### 3. `browser-e2e`

Playwright (or Stagehand) end-to-end test against the running application.
Generated by Sentinel (`sentinel.run` → `sentinel.augment` if coverage gap)
where missing.

**Required when (UI-surface heuristic):**

- Changed file matches `*.tsx`, `*.jsx`, `*.vue`, `*.svelte`,
  `app/**/page.*`, `pages/**`, or any component file.
- Authentication / authorization / routing logic changed.
- Form validation, input handling, or user-facing error path changed.
- Public navigation graph changed (new route, removed route, redirect).

**What it must do:**

- Hit the actual rendered page in a browser, not a JSDOM stub.
- Click the relevant buttons, fill the relevant fields, traverse the
  relevant flow.
- Assert on user-visible state (DOM, URL, network calls), not just
  internal component state.
- For each touched form: at least one happy-path submission, one
  invalid-input submission, one boundary-condition submission.

### 4. `data-combo`

Property-based + contract-based tests for input-space coverage. Two
sub-flavors selected per surface:

#### 4a. API contract (when OpenAPI / GraphQL schema present)

Run `schemathesis run <spec-url-or-file> --base-url <running-server>`.

- Schemathesis generates input combinations from the schema and asserts
  the live server's responses validate against it.
- Failures: schema violations, 5xx responses, response-shape drift.

#### 4b. Function-level (no schema, pure functions)

- Python: `hypothesis` strategies for each public function.
- TS/JS: `fast-check` properties for each public function.

**Required when:**

- New public API endpoint added.
- Schema or contract changed (OpenAPI, GraphQL, type-level public
  interface).
- Input-validation layer touched.
- Pure-function utility with non-trivial input space (parsers, formatters,
  serializers, validators).

**What it must do:**

- For API: run schemathesis to completion; non-zero exit blocks slice.
- For function-level: at least 3 properties per surface (boundary,
  invariant, error-symmetry). Run with at least 100 generated cases.

## Adjacent Escalation Rule

The most common LLM cheat: change a deeply-imported helper, run that one
file's tests, declare done. Adjacent code that depended on the helper is
silently broken.

**The rule:**

1. After producing the diff, compute the changed-files set.
2. For each changed file, compute the reverse-import set at depth ≤ 2:
   - JS/TS: `dependency-cruiser --output-type json <file>` →
     parse `modules[].dependents` recursively to depth 2.
   - Python: `grimp` to build the import graph; `graph.find_descendants(<module>)`
     up to depth 2.
3. Intersect that set with the project's covered-surface set (files that
   have tests).
4. For each surface in the intersection, escalate that surface's required
   breadth to `full` (and `browser-e2e` if it matches the UI heuristic).
5. The validator agent runs the escalated breadths before marking the
   slice accepted.

**Why depth ≤ 2:** depth 1 catches direct callers; depth 2 catches the
common pattern of helper → service → API. Beyond depth 2 the signal-to-
noise ratio drops and full-suite is more efficient.

## Gate Mechanics

The `test_breadth_check` postflight gate (in `route_manifest.json`'s
`gate_chain` ahead of `validate_impl`) does **not** run the tests
itself. It:

1. Reads the slice's diff from track state.
2. Classifies each changed file against the trigger rules above.
3. Computes the adjacent-escalation set.
4. Emits `required_breadths` to track state, structured as:
   ```json
   {
     "required_breadths": {
       "smoke": ["src/util/format.ts"],
       "full": ["src/util/format.ts", "src/api/orders.ts"],
       "browser-e2e": ["src/pages/checkout.tsx"],
       "data-combo": {
         "api": ["openapi.yaml"],
         "function": ["src/util/format.ts"]
       }
     }
   }
   ```
5. The `validator` agent reads this and runs the appropriate harnesses.
   Slice cannot accept until evidence exists for each required breadth.

## Bypass

If a tooling failure prevents a breadth from running (e.g. Sentinel
container down, Playwright browsers not installed), the gate fails closed
unless the operator passes `--breadth-bypass <reason>` on the slice
acceptance call. The bypass is recorded in track state and surfaces in
the postflight scorecard. No silent skips.

## Anti-Patterns

The following are explicit cheats that fail this standard:

- **Mocking the database to make a test pass.** Integration tests must
  hit the real (test-scope) database. (See feedback memory:
  `feedback_integration_test_use_global` and similar Chad guidance.)
- **`if (process.env.NODE_ENV === "test") return early;`.** Hiding
  behavior from tests.
- **Adding a `skip` or `xfail` to make CI green.** Skip-control debt
  fails the enterprise rubric's `strict-skip-control-zero` hard gate.
- **Asserting only on internal state when external state is the
  contract.** A button click test that checks a flag in component state
  but not the network call or DOM update is not a real test.
- **One assertion per test that just checks `truthy`.** Schemathesis and
  hypothesis exist precisely to avoid this; use them for any non-trivial
  function.
- **Smoke-testing a UI change because the test framework "feels"
  insufficient.** If browser-e2e is required, generate it via Sentinel
  and run it. The framework is not the bottleneck.

## Output Contract

The `test_breadth_check` gate emits, per slice:

- `required_breadths` — structured set as above.
- `evidence_pointers` — paths to the test files / harness output that
  satisfy each breadth (filled in by `validator` post-run).
- `escalations` — list of files whose breadth was escalated by the
  adjacency rule, with the depth-2 path that triggered it.
- `bypass` — null or `{ "breadth": "...", "reason": "...", "operator": "..." }`.

`validator` returns failure if any required breadth has no evidence and
no bypass.
